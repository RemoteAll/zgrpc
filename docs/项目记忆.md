# zgrpc 项目记忆

> 本文件是仓库镜像（随 git 版本化）；本机工作记忆由 `tools/continuity/sync-memory.ps1` 同步。

## 结构与口径

- 零依赖，只用标准库；**不依赖 zzig**（zzig 要集成就走可选依赖 + 薄适配）。
- 分层：`hpack` → `h2` → `grpc`；每层可独立测试，改动必须补用例。
- `src/hpack_huffman_table.zig` 是生成文件，勿手改（数据来自 RFC 7541 附录 B）。

## 已验证的事实

- `zig build test` → 23/23 通过（含 h2 端到端帧断言、gRPC unary/多路复用、客户端解析、**bidi 流式与跨帧重组、gRPC-Web 尾帧**）。
- **双向对拍已验证**（用 Rust hyper 当裁判，`tools/interop-rust`）：
  Rust 客户端（原生 + gRPC-Web）→ zgrpc 服务端全通；zgrpc 客户端 → Rust 服务端全通。
- 真实 socket：`echo-client` 在同一 TCP 连接上并发两条流，均 `grpc-status=0`。
- 示例端口用 **18051**（50051 在本机被其它进程占用，bind 报 `ACCESS_DENIED`）。

## 踩过的坑（Zig 0.17）

- `GeneralPurposeAllocator` 已移除；`main(init: std.process.Init)` + `Args.Iterator.initAllocator`。
- `std.Io.Dir` 方法需传 `io`；`Reader.readSliceAll` 的 EOF 是 `error.EndOfStream`。
- `@embedFile` 不能跨包路径。
- RST_STREAM 的 payload 是 4 字节错误码；SETTINGS 的 ACK 帧长度必须为 0。
- HPACK 叶子编码曾用 `-1 - sym`，与「空槽 = -1」撞车（sym 0 时）→ 改 `-2 - sym` 并把 EOS 排除出树。

## 服务反射（2026-11-13）

- 三层：`src/proto.zig`（proto3 子集解析）→ `src/descriptor.zig`（→ `FileDescriptorProto`）→ `src/reflection.zig`（`ServerReflectionInfo` 双向流）。
- 路由：`refl.streamRoute()` / `streamRouteV1Alpha()` 走 **per-route `ctx`**（`route.ctx orelse server.outer_ctx`），不与业务路由抢 `outer_ctx`。
- 数据用内部 `ArenaAllocator` 长期持有，`deinit` 只需 `arena.deinit()`（逐个 free 会漏中间串，测试报 "1 tests leaked memory"）。
- **`FieldDescriptorProto.type` 必须与 `type_name` 指向的定义一致**：enum→`14`、message→`11`。写错 → `grpcurl describe` 报
  `resolved "X", but it is not an message`（第一版就是这样，`list` 能过、`describe` 全挂）。
- 验证：`grpcurl -plaintext HOST list` / `describe Svc` / `describe Msg` / `-d JSON` 直接调用；测试 **64/64**。

## 回归脚本的 Windows 坑（2026-11-13 实测）

- **zombie `LISTEN`**：`Stop-Process -Force`（= `TerminateProcess`）后监听 socket 留在 `netstat` 里
  `OwningProcess=0` 的 `LISTENING` 状态，几十秒不消失且无法 kill。固定端口会让**下一次回归所有用端口的段全 SKIP**
  → 每段必须用 `Get-FreePort` 随机端口（`echo-server` 支持 `--port N`）。
- `Get-NetTCPConnection -LocalPort X` 会把 `TIME_WAIT` 一起返回 → 判定占用必须加 `-State Listen`。
- PS 5.1 调原生 exe 会**吞掉内层双引号**：`-d '{"a":1}'` 变成 `{a:1}`（`invalid character 'a'`）→ 改 `-d '@'` 从 stdin 喂。
- here-string `@'...'@` 的换行是 LF，目标文件是 CRLF 时 `String.Replace` **静默不匹配**；
  按行改文件要核对 `ReadAllLines` 数组切片边界（PS 切片含两端，`$l[0..102]` 是 1..103 行）。
## import 跨文件（2026-11-13）

- `src/proto_loader.zig`：递归加载 + 拓扑排序 + 菱形去重 + 循环报错；单文件 8 MiB 上限；`Loader.memory` 供单测注入内容。
- **口径同 protoc**：import 按 **root 目录**解析（等价单一 `-I`），不是相对引用方目录；`FileDescriptorProto.name` = 相对 root 的路径（import 写什么就是什么）。
- 反射 `Service.fromLoaded`：每文件一份 descriptor，`dependency` 写 import 原样路径。
- **跨包类型判定必须有多文件上下文**：`descriptor.encodeFileWith(..., all)`；`proto.findMessage/findEnum/qualifiedName` 的递归**初始 prefix 用 `p.package`**（否则 `common.Region` 匹配不上，会被编成 message）。
- 示例：`zig build import-server -- --port N --proto examples/proto_import/shop.proto`；回归「import」段实测 describe + 依赖文件 + 跨包 enum 往返。
- **codegen 仍只支持单文件**（遇 import 报 `UnknownType`）—— 跨文件生成要在「合并单文件」与「每 proto 一个 .pb.zig」之间取舍，属破坏性设计，待确认。
## codegen 跨文件（2026-11-13，protoc 风格）

- 口径：**每个 .proto 生成自己的 .pb.zig**，跨文件引用 `const <alias> = @import("<path>.pb.zig");` + `<alias>.<Type>`。
  单文件场景生成结果**完全不变**（另一种「合并单文件 + 包前缀」方案破坏性太大，已否决）。
- `proto_gen` 的 `Ctx`：`own`（本文件裸名）/ `global`（`别名.类型`）两张表；登记时同时登记各级后缀
  （`Container.Nested` 也登 `Nested`）；`@import` 只登记**本文件 imports 里直接声明的**文件（否则会反向依赖）。
- 一次 `proto_gen root.proto out.zig` 会**顺带生成全部依赖**到 `<out_dir>/<name>.pb.zig`；约定输出文件与 root 同目录。
- 示例：`examples/proto_import/`（shop.proto + common/types.proto → 两份 .pb.zig）+ `examples/shop_pb_test.zig`。
- `zig build codegen` 同时生成 echo 与 shop 两套。
